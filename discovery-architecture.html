02
⚡ Flow Controller (Mixed)
DiscoveryEngine.tsx — everything lives here
Stage routing + state + scoring normalization all mixed
What DiscoveryEngine.tsx actually does (all at once):
• Owns all session state (stage, mode, scores, signals, aiResult)
• Controls all stage transitions (transitionToStage)
• Applies score updates (addScores)
• Performs score normalization (normalizeScore function inline)
• Renders the full UI shell (sidebar, wipe overlay, grain texture)
• Routes Quick vs Deep mode branching
• Calls getArchetype() for archetype resolution
  • normalizeScore() is a pure math function living inside a React component — should be in core/scoring.ts
  • Stage transitions use setTimeout directly — fragile, hard to test
  • DOT_NAV_STAGES is UI config mixed with flow logic
  • ✓ Fix: Extract scoring + normalization to core/. Keep DiscoveryEngine as pure orchestrator.
03
📊 Scoring Logic (Scattered)
Score deltas live inside each UI component
No central scoring model — each component owns its own weights
Scoring happens in 6+ different components. The addScores() function in DiscoveryEngine receives partial score objects emitted by each child. The weight mappings are hardcoded inside those children — meaning to understand the full scoring model you must read 6 files simultaneously.
  • AdjectiveSelection.tsx — contains hardcoded word-to-score map (Calm, Warm, Bold, etc.)
  • VisualInstinct.tsx — image tags map to score deltas via constants/discovery
  • EmotionalMapping.tsx — slider positions emit partial scores
  • MaterialResonance.tsx — material choice emits score delta
  • LightCalibration.tsx — light type emits score delta
  • LifestyleReflection.tsx — lifestyle choices emit score deltas
  • ✓ Fix: Create core/scoring.ts with all weight maps. Components only call score(key, value) — no maps inside UI.
04
✓ AI + Integration Layer
Supabase edge functions — reasonably isolated
Relatively clean — two edge functions, proper error handling
Two Supabase edge functions:
• aesthetic-ai — called by AnalysisPhase, receives full UserSignals, returns AIAestheticResult. Has fallback if AI fails (toast + fallback archetype).
• submit-discovery-lead — called by LeadGatePhase, saves name/email/phone + scores to DB.
  • ✓ AI call is cancellable (cancelled ref pattern) — good async hygiene
  • ✓ Graceful fallback if edge function fails
  • Both edge functions called from UI components directly — no abstraction layer between component and API
  • No retry logic on network failure
  • ✓ Fix: Create infrastructure/api.ts with callAI() and submitLead() wrappers.
05
⚠ Page Coupling
pages/DiscoveryPage.tsx + pages/BlueprintPage.tsx
Engine tied to app router — not portable as addon
  • DiscoveryPage wraps DiscoveryEngine with react-helmet-async + react-router Link — engine depends on router
  • BlueprintPage.tsx is 1,074 lines — massive single file with inline CSS + chart logic + archetype data all together
  • Engine cannot be embedded in any other site without bringing entire router + page structure
  • ✓ Fix: Create DiscoveryAddon.tsx as pure mount point. Router/page wrapper becomes external. Engine receives config as props.
06
⚠ Analytics — Does Not Exist
No event tracking, no session model, no completion metrics
Cannot measure drop rate, completion %, archetype distribution
  • Zero event tracking in any component — no way to know where users drop
  • No session ID system — cannot correlate events across stages
  • Lead is only recorded on form submit — if user drops before gate, zero data captured
  • No way to measure Quick vs Deep completion rates
  • ✓ Fix: infrastructure/analytics/tracker.ts → track(event, payload). Wrap in try/catch. Non-blocking.

Scoring Model — Where Scores Are Updated

5-axis model: minimalism · warmth · social · structure · novelty. All start at 5, clamped 0–10, then normalized to 1–9 on output.

Normalization formula (in DiscoveryEngine.tsx, inline):
centered = (raw - 5) / 5  →  compressed = centered × 0.7  →  output = 5 + compressed × 5  →  clamp(1, 9)
This compresses extreme scores toward center — prevents 0/10 outputs.

Issues & Recommended Fixes

Ordered by business impact. Fix critical issues before any hero launch.

● CRITICAL
UI Folder Duplicated Inside Addon
49 shadcn component files exist inside discovery/components/ui/ — duplicating the entire shared design system. This inflates bundle size, creates two sources of truth, and makes the addon non-portable.
FIX
Delete discovery/components/ui/
Update all imports to @/components/ui
Verify build still compiles
● CRITICAL
Scoring Logic Scattered Across 6 UI Files
Score weight maps are hardcoded inside AdjectiveSelection, EmotionalMapping, MaterialResonance, LightCalibration, LifestyleReflection, and VisualInstinct. No single place to understand the full scoring model.
FIX
Create: core/scoring.ts
Export: ADJECTIVE_WEIGHTS, MATERIAL_WEIGHTS, etc.
Components only call: onComplete(score("warmth", +2))
● CRITICAL
Lead Gate Blocks Results (Pre-Gratification)
Users complete 10 phases, then hit a form wall before seeing any result. This is the single highest drop-risk point. Effort already invested — but reward still blocked.
FIX
Flow: Analysis → Mini Result Preview
→ "Unlock Full Blueprint" gate
→ Full ResultsReveal
Show archetype name + 3 traits free.
● CRITICAL
Zero Analytics — No Drop Tracking
No event tracking exists anywhere in the engine. It is impossible to know where users abandon, what archetype distribution looks like, or whether Quick mode converts better than Deep.
FIX
Create: infrastructure/analytics/tracker.ts
track(event, payload) — non-blocking
Fire on: start, each step_viewed, submit, restart
● MEDIUM
normalizeScore() Living Inside React Component
Score normalization math is defined as an inline function inside DiscoveryEngine.tsx — a React component. Pure logic has no place inside a render scope.
FIX
Move to core/scoring.ts
export const normalizeScore = (raw: number): number => ...
● MEDIUM
BlueprintPage.tsx — 1,074 Lines, Monolithic
The output page is a single 1,074-line file mixing archetype data, chart rendering, moodboard logic, and PDF generation. Hard to maintain and extends initial load.
FIX
Split: BlueprintHeader, BlueprintRadar, BlueprintMoodboard
Lazy load: ResultsReveal and BlueprintPage
Preload blueprint chunk at PatternPreview stage
● MEDIUM
Quick Mode Gets Equal-Weight Results
Quick mode skips Adjective, Emotional, and PatternPreview phases — significantly fewer signals — but ResultsReveal presents output identically to Deep mode. Users can't tell the difference.
FIX

CTA: "Get your full Spatial Blueprint"
● MEDIUM
No Micro Progress in Reflection (8 sections)
The Reflection Prompt has 8 sub-sections with 15 questions, but no visible per-section progress or estimated time. Users can't see how far they are inside the reflection phase.
