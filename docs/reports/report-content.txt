When <Navbar> and <Footer> are rendered inside the <main> element, screen reader software announces the entire page as a single region, eliminating the ability to jump between sections. This violates the foundational navigation contract for assistive technology users.Current structure (INCORRECT):<main>  <Navbar />        {/* ❌ Should NOT be inside <main> */}  <HeroSection />  <ServicesSection />  ...  <Footer />        {/* ❌ Should NOT be inside <main> */}</main>Required structure (CORRECT):<Navbar />           {/* ✅ Top-level landmark */}<main>  <HeroSection />  <ServicesSection />  ...</main><Footer />           {/* ✅ Top-level landmark */}File to Modify: src/Index.tsxRisk Level: Low — visual layout unchanged; semantic-only restructureTest Verification: Use WAVE or axe to confirm nav, main, footer are peer-level landmarksIssue 2 — Nested Interactive Controls in Portfolio Cards  [CRITICAL]🔴 WCAG 2.1 SC 4.1.2: Name, Role, ValueThe Portfolio component wraps each project <article> with role='button' and tabIndex={0}, then places a <button> (lightbox trigger) and a <Link> (View Full Project) inside it. Screen readers cannot reliably interpret nested interactive elements — the outer role='button' intercepts all child interactions, making the inner button and link inaccessible to keyboard and AT users.Problem pattern:<article role='button' tabIndex={0}>   {/* ❌ */}  <button onClick={openLightbox}>       {/* ❌ Nested inside role=button */}    <img src={project.thumbnail} />  </button>  <Link to={project.url}>              {/* ❌ Nested link */}    View Full Project  </Link></article>Required fix:<article>                               {/* ✅ Plain article, no role */}  <button onClick={openLightbox}        {/* ✅ Direct lightbox trigger */}    aria-label={`Open ${project.title} gallery`}>    <img src={project.thumbnail} alt=''/> {/* alt='' — title is in button */}  </button>  <Link to={project.url}>              {/* ✅ Independent interactive element */}    View Full Project  </Link></article>File to Modify: src/components/Portfolio.tsxLines Affected: Article wrapper (~L42), button element (~L48), Link element (~L56)Test Verification: Tab through Portfolio: focus must hit image button then link separatelyIssue 3 — Redundant Alt Text on BeforeAfterShowcase  [SERIOUS]🟠 WCAG 2.1 SC 1.1.1: Non-text ContentIn the BeforeAfterShowcase component, each project thumbnail <img> carries the full project title as its alt attribute. The containing <button> or label element already presents that title as text. Screen readers announce the title twice — once from the image alt and once from the surrounding text — creating a confusing experience.Current (causes double-reading):<img src={thumb.url} alt={project.title} />   {/* ❌ */}<span className="sr-only">{project.title}</span>Required fix — decorative image:<img src={thumb.url} alt="" />               {/* ✅ decorative */}<span className="sr-only">{project.title}</span>File to Modify: src/components/BeforeAfterShowcase.tsxTest Verification: NVDA announces title once per thumbnail. No 'graphic' announcement.Issue 4 — Scrollable Thumbnail Strip Not Keyboard Accessible  [SERIOUS]🟠 WCAG 2.1 SC 2.1.1: KeyboardThe lightbox dialog in Portfolio.tsx contains a horizontally scrollable strip of project thumbnails. This container has overflow-x: scroll but no tabIndex or role attribute. Keyboard users and screen reader users cannot scroll or navigate this strip without a pointing device.Required fix — add ARIA attributes to scrollable container:<div  className="thumbnail-scroll-strip"  tabIndex={0}  role="region"  aria-label="Project thumbnails">  {/* thumbnails */}</div>File to Modify: src/components/Portfolio.tsx (Lightbox sub-component)Test Verification: Tab reaches strip; arrow keys scroll; screen reader announces region labelIssue 5 — Incorrect role='button' on Article Element  [MODERATE]The role='button' attribute on the <article> wrapper (covered in Issue 2) also independently violates WCAG 4.1.2 because the article element does not support implicit or explicit button semantics. The fix outlined in Issue 2 removes this attribute, resolving both violations simultaneously.3.3 Lighthouse Scores (Pre-Fix Baseline)CategoryScore (Pre-Fix)TargetGradeAccessibility67 / 100≥ 90FAILPerformance84 / 100≥ 90WARNBest Practices91 / 100≥ 90PASSSEO88 / 100≥ 90WARNPWAN/AOptionalINFO4.
