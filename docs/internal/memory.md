## 2. BUSINESS PURPOSE

Cross Angle Interior is a luxury interior design studio based in Jamshedpur, Jharkhand (India). The platform serves two primary audiences:

**Public Visitors (Prospects):**
- Browse portfolio of completed interior design projects
- Read service descriptions (living rooms, kitchens, bedrooms, commercial, etc.)
- Read blog articles about interior design trends
- View the gallery of real project photos
- Use the Cost Estimator to get a project budget range
- Take the Aesthetic Discovery Engine quiz to identify their design style
- Submit lead forms (contact, consultation request, estimate)

**Studio Team (Admin):**
- Manage all public content (blogs, portfolio, services, testimonials, gallery)
- View and manage leads (CRM pipeline)
- Configure pricing for the estimator
- Review quiz/discovery analytics
- Manage team members and user access/roles
- Configure site-wide settings (logo, contact info, social links, maintenance mode)
- Access audit logs and email templates

**Business Model:** Lead capture → consultation booking → interior design project delivery

## 6. AUTHENTICATION FLOW

```
1. User navigates to /admin/auth
2. AdminAuth.tsx renders login form
3. supabase.auth.signInWithPassword({ email, password }) called
4. Supabase returns JWT session → stored in localStorage
5. AuthProvider (onAuthStateChange listener) picks up session
6. AuthGuard (React Router nested route) checks session exists
7. RoleGuard checks profiles.role ('super_admin' | 'admin' | 'viewer')
8. profiles table auto-created via DB trigger on auth.users INSERT
9. Access token sent as Authorization: Bearer <token> header on all requests

Unauthenticated → redirect to /admin/auth
Mobile device → 403 (blocked by Vercel Edge middleware before React loads)

Edge functions using service_role:
- manage-user (suspend/delete/unsuspend)
- invite-user (send email invites)
- assign-first-admin (initial setup)

Roles hierarchy:
- super_admin → full access including sensitive routes
- admin → most admin routes (no role management, no audit config)
- viewer → read-only dashboard (UNKNOWN - verify RoleGuard for viewer paths)
```

## 7. DATA FLOW PATTERN

```
User Action
  → React Component
    → useQuery / useMutation (@tanstack/react-query)
      → supabase client (from @/integrations/supabase/client)
        → Supabase PostgREST API (auto-REST from schema)
          → PostgreSQL with RLS policies
            → Response cached by React Query (staleTime: 5 min, gcTime: 30 min)
              → UI updates reactively

On mutation success:
  queryClient.invalidateQueries({ queryKey: [...] })
  → triggers refetch → UI updates

For edge functions:
  invokeEdge('function-name', { ...payload })
  → supabase.functions.invoke() or fetch to SUPABASE_URL/functions/v1/
  → JWT sent if authenticated session exists
```

## 16. PERFORMANCE NOTES

- **Chunk budget:** 250 KB limit enforced in Vite config — alerts if exceeded
- **Lazy loading:** ALL page components are lazy (`React.lazy`) — routes split on load
- **Idle loading:** Smooth scroll (Lenis) deferred with `runWhenIdle()` — doesn't block FCP
- **Images:** ImageKit CDN with auto-format and transformations
- **Caching:** React Query (staleTime 5min), CDN (1yr immutable for assets)
- **Analytics:** PostHog self-proxied through Vercel `/ingest` rewrite — avoids adblockers
- **Three.js:** Loaded in its own chunk — only loads when 3D component mounts
- **OG Injection:** Done in Edge middleware, not SSR — no server overhead for real users

### Potential Bottlenecks
- `types.ts` is 167 KB (type-only, stripped at build, no runtime cost)
- `BlueprintPage.tsx` is 108 KB — largest single component file (UNKNOWN — needs audit)
- No visible N+1 query protection in PostgREST calls — verify joins are used

## 20. KNOWN RISKS
