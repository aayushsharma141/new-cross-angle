<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public form -> lead row -> email HTML | Name/service/message are untrusted text |
| DB trigger / cron -> handle-new-lead | Bearer secret authenticates the caller |
| Public anon JWT -> auto-reply-lead | Was callable by anyone |
| handle-new-lead -> Resend | Outbound mail to customers and staff |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-05-01 | Spoofing / abuse (mail relay) | auto-reply-lead | mitigate | Task 3: trusted caller only; recipient and fields from DB row by leadId |
| T-40-05-02 | Tampering (HTML injection) | customer + internal email bodies | mitigate | Task 1 escapes all substitutions incl. custom templates; test with `<script>` |
| T-40-05-03 | Spoofing | handle-new-lead endpoint | mitigate | Task 2: constant-time bearer compare vs WEBHOOK_SECRET / service key; sweep requires service key |
| T-40-05-04 | Denial of service / spam | duplicate sends on retry or concurrent call | mitigate | Task 2 claim-then-send on *_at columns with release on failure (unit-proved in 40-02) |
| T-40-05-05 | Information disclosure | logs / HTTP response | mitigate | Task 2: no addresses, secrets or Resend bodies in logs/responses; activity metadata stores counts only |
| T-40-05-06 | Repudiation | notification outcome unknown | mitigate | lead_activities rows for sent and failed outcomes with trace_id |
| T-40-05-07 | Denial of service | historic backfill email storm | mitigate | Sweep requires `since` cutoff and 20-lead cap; no backfill of timestamps |
| T-40-05-SC | Tampering | npm/pip/cargo installs | accept | No packages; esm.sh supabase-js version already pinned by existing code |
