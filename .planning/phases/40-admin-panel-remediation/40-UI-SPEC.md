## Spacing Scale

Declared values (all multiples of 4; Tailwind default scale, which the admin already uses):

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `gap-1`, `p-1` | Icon-to-icon gaps in row action clusters, pill vertical padding |
| sm | 8px | `gap-2`, `space-y-2` | Input + "Add" button gap; gap between list rows; icon-to-label gap in buttons (built into Button) |
| md | 16px | `p-4`, `px-4`, `space-y-4`, `gap-4` | List-row horizontal padding; space between fields inside a card; idle dialog body spacing |
| lg | 24px | `space-y-6`, `gap-6` | Between stacked cards on a page; between fields in CMS editor form; between MFA steps |
| xl | 32px | `p-8`, `mb-8` | AdminAuth card padding (existing `p-8`); gap under auth headline (existing `mb-8`) |
| 2xl | 48px | `py-12` | Not used by new surfaces (reserved) |
| 3xl | 64px | `py-16` | Not used by new surfaces (reserved) |

Exceptions (all pre-existing, locked — do not "normalise" them, that would be a visual regression):
- **12px** (`py-3`, `gap-3`): recipient list row vertical padding and icon-to-text gap (ReportRecipientsManager); Site Content nav item padding.
- **20px** (`p-5`, `px-5`): `AdminFormCard` body and header horizontal padding.
- **40px** (`md:p-10`): AdminAuth card padding at ≥ md.
- **Control heights:** Button `default` 40px (`h-10`), `sm` 36px (`h-9`), `icon` 40×40; in-row remove icon buttons 32×32 (`h-8 w-8`, existing recipient-row pattern); AdminAuth inputs and primary button 56px (`h-14`, existing). The 6-digit code input on the auth card uses `h-14` to match.
- **QR code tile:** 192×192 px image inside 12px white padding (`p-3 bg-white rounded-2xl`) = 216px tile. White is required for scanner contrast (the only place a light surface is allowed in admin).

## Surface Contracts

### S1. Two-factor sign-in (D-07, D-08, D-10)

**Where:** new `AuthView` values in `pages/admin/AdminAuth.tsx`: `'mfa-challenge' | 'mfa-enroll' | 'mfa-expired'`, rendered inside the existing card (`max-w-[440px]`, `bg-[#1A1A1A] rounded-3xl p-8 md:p-10`), with the existing framer-motion transition (`opacity 0→1, x -10→0`, `AnimatePresence mode="wait"`).

**Flow:**
1. Password submit → `/api/auth/login` returns `{ mfa: 'challenge' }` → view `mfa-challenge`; returns `{ mfa: 'enroll' }` → view `mfa-enroll`. No other response shape changes the existing login behaviour.
2. "Keep me logged in" choice from step 1 is carried into the final redirect (TTL write happens after verify succeeds, not after password).
3. Verify success → in-card state "Signing you in…" (Loader2 + body text) → existing hard navigation to `ROLE_DEFAULT_ROUTE[role]`.

**`mfa-challenge` layout (top→bottom, `space-y-6`):**
- Display headline (30px serif) + 12px uppercase eyebrow under it (existing pattern).
- Body text (14px, `text-zinc-400`).
- `OneTimeCodeInput`: label "6-digit code" (12px uppercase), `h-14`, `rounded-2xl`, same fill classes as login inputs, text 20px `font-mono tracking-[0.5em] text-center`, `inputMode="numeric"`, `autoComplete="one-time-code"`, `maxLength={6}`, strips non-digits on input, autofocus on mount.
- Inline error slot directly under the input (14px, rose/destructive text, `role="alert"`), reserved height 20px so layout does not jump.
- Primary button full width `h-14` (existing login button classes). Disabled until 6 digits.
- Secondary text buttons (12px, existing "Return to Login" style): "Lost your phone?" (expands a help paragraph in place, `aria-expanded`), "Use a different account" (returns to `login`, clears password).

**`mfa-enroll` layout (`space-y-6`):**
- Optional rollout banner (only when the server says enforcement triggered the enrolment): bordered note, `rounded-2xl`, `bg-amber-500/5 border border-amber-500/20`, 14px text.
- Display headline + eyebrow.
- Three numbered steps (existing check-email step-chip markup): chip 20px circle, 12px number, 14px text.
- Step 2 contains the QR tile (192px `<img src={qr_code}>` from GoTrue's `totp.qr_code`, centred, `p-3 bg-white rounded-2xl`). Under it a disclosure button "Can't scan? Type a setup key instead" (`aria-expanded`). Expanded: the secret in 14px `font-mono`, grouped in blocks of 4 with spaces, `select-all`, plus an icon button (32px) `aria-label="Copy setup key"` → toast.
- Step 3 contains `OneTimeCodeInput` + error slot (same as challenge).
- Primary button "Verify and continue".
- Text button "Cancel and log out" (calls logout, returns to `login`).

**`mfa-expired`:** reuses the existing `expired` view layout (rose icon tile, headline, body, one button).

**States:** idle → submitting (button spinner, input `aria-busy`, disabled) → error (inline message, input keeps focus and is selected for retype; button re-enabled) → success (Signing you in…). Wrong code never clears the "Keep me logged in" choice.

### S4. Idle logout warning (D-09)

**Where:** `IdleWarningDialog`, mounted once in `pages/admin/AdminLayout.tsx`, driven by `useIdleLogout(minutes)`.
- Component: `AlertDialog` (role `alertdialog`), content className `admin-theme bg-admin-card border-admin-border text-admin-text sm:max-w-md`, wrapped in `FocusLock returnFocus` like `ConfirmDialog`.
- Appears at T − 2:00. Outside-click does nothing; `Escape` = "Stay signed in".
- Body order: title → description → countdown line (20px / 600, `tabular-nums`, format `m:ss`, e.g. `1:59`) → footer.
- Footer: primary "Stay signed in" (autofocus), outline "Log out now".
- Screen readers: countdown element is `aria-hidden`; a visually hidden `aria-live="polite"` region announces only at open, at 1:00 and at 0:30.
- Cross-tab: activity or "Stay signed in" in any tab closes the dialog in every tab (shared `localStorage` timestamp).
- At 0:00: call `useAuth().signOut()`, navigate to `/admin/auth?reason=idle`. AdminAuth then shows the `login` view with an info note above the form (`rounded-2xl bg-sky-500/5 border border-sky-500/20`, 14px; sky matches the AdminAuth raw-color convention).
- "Stay signed in" shows no toast (closing the dialog is the visible result).

## Interaction Rules (apply to every surface touched in this phase)

1. **Every save shows a result.** Each Save / Publish / Add / Remove / Lock / Reset fires exactly one toast: success = default variant, failure = `variant: "destructive"`. Silent `catch` blocks that only `console.error` are not allowed on touched paths (audit M4: Lead Workspace lock, Settings, Blog Performance, Blog Engagement, Learning Health). Errors also go to `captureException` where the file already imports it.
2. **Pending state.** The triggering button shows `Loader2` (`h-4 w-4 animate-spin`) and is disabled; other actions in the same card are disabled; the label stays the same or switches to a present-participle form ("Locking…", "Saving…").
3. **Styled confirmations only.** No `window.confirm` / `alert` anywhere in admin after this phase (Gallery delete and the Site Content block switch are the known cases). Use `ConfirmDialog`; destructive actions pass `variant="destructive"`; cancel label defaults to "Cancel" unless the table below says otherwise.
4. **Icon-only buttons have names.** Every `size="icon"` or icon-only button has an `aria-label` written as verb + object ("Remove chat ID 1228126069", "Copy setup key", "Back to leads"). Covers the audit's 21 unlabelled buttons (Estimator and Discovery editors, Quote Requests) and the unlabelled remove button in `ReportRecipientsManager`.
5. **Focus.** Visible `focus-visible:ring-2` in admin gold on every new interactive element; dialogs trap focus and return it to the trigger; the first input in each MFA view and "Stay signed in" get autofocus.
6. **Inline field errors** sit directly under the field (14px, `--admin-danger`, `X` icon 12px, existing password-form pattern) and are linked with `aria-describedby`; banners use the existing `role="alert"` danger box (Site Content L320).
7. **Never claim what isn't true (D-10).** A control whose effect is not wired shows a warning pill "Not active yet" plus one sentence saying what will happen once it is. The two false toasts ("All admin users will be required to set up two-factor authentication", "Inactive users will be logged out after N minutes") are replaced by the copy below.
8. **Motion.** Reuse existing motion only: AdminAuth view transitions (framer-motion `opacity` + `x ±10`), Radix dialog fade/zoom, toast slide. No new animation.
