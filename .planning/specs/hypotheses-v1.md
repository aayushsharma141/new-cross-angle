# Hypotheses v1.0

This document defines the core falsifiable hypotheses that the Crossangle platform exists to test. These hypotheses form the benchmark against which the success of the learning engine, and the platform as a whole, will be evaluated. 

Every hypothesis must eventually transition from `Untested` to `Confirmed`, `Rejected`, or `Inconclusive` based on empirical evidence from the Learning Engine.

| ID | Hypothesis | Success Criterion | Status |
|---|---|---|---|
| H0 | The platform can reliably associate operational events with immutable learning records. | Evidence chain is unbroken from action to telemetry | Supported |
| H1 | The Workspace increases Designer Confidence Delta | Median DCD > 0 across Dataset v1 | Untested |
| H2 | Evidence-backed recommendations improve expert agreement | Expert agreement improves vs. baseline | Untested |
| H3 | Explainability increases recommendation acceptance without reducing decision quality | Acceptance increases while DQI is maintained | Untested |
| H4 | The Decision Ledger enables reproducible replay across algorithm versions | 100% replay fidelity | Untested |
| H5 | DQI correlates positively with project outcomes | Positive correlation after validated outcomes | Untested |
| H6 | A locked architecture with explicit governance improves system stability | Zero un-governed L3/L4 changes made during Dataset v1 | Untested |

*If Dataset v1 disproves one of these original beliefs, that is exactly what this learning system is designed to reveal. A rejected hypothesis is a successful scientific outcome.*
